## Operator review finding

An outside audit reviewed the actual T2 snapshot, preserved evidence, tests, gates, and
runtime implementation. It found that the implementation was substantially aligned with
the approved T2 scope, but identified two T2 correctness blockers that the previous gate
did not detect:

1. T2 receipts, artifacts, and App Journal CLI paths could use `storage.connect()`
   without the SQLite instance identity check performed by `storage.bootstrap()`.
2. Receipt completion could persist an operational artifact in one transaction and then
   fail to update the receipt in a second transaction, leaving an orphan artifact whose
   embedded envelope claimed durable governance.

The audit also identified two evidence holes: the successful immediate `write_file`
route lacked direct receipt/artifact inspection, and App Journal independence lacked a
fresh witness where a journal entry exists while operation receipts remain empty.

Entry `0019` remains immutable historical evidence for the previous review submission.
This entry supersedes `0019` only as the current T2 review submission.

## What changed

`product/core/storage.py` now verifies existing SQLite instance ownership before applying
migrations. `storage.connect()` delegates through `storage.bootstrap()`, so all T2
runtime-memory entrances share the same trusted state-owner check.

`product/core/runtime_records.py` now persists the operational artifact row and completes
the receipt row in one SQLite transaction. If receipt completion fails after a child
process has already run, no orphan artifact is left claiming `durably_governed = true`.

`tests/test_t2_runtime_memory.py` now contains explicit fixtures for:

- T2 receipt/artifact/journal CLI refusal when SQLite identity disagrees with
  `instance.json`;
- refusal before migration when a mismatched legacy schema-v1 database is encountered;
- successful `write_file` receipt and artifact inspection;
- receipt-finalization failure after a real write, proving no orphan artifact remains;
- an App Journal entry created in a fresh runtime while receipts remain empty.

`.builder/gates/t2_runtime_receipts_work_memory.py` now has 13 checks instead of 11. It
adds positive checks for trusted state ownership and coherent receipt completion, and its
discrimination witness rejects unverified storage connection, migration before identity
refusal, split artifact/receipt completion, journal/receipt table collapse, automatic
receipt-to-journal projection, and missing receipt failure guard.

`docs/ARCHITECTURE.md` now describes the actual control-plane ordering: trusted state is
bootstrapped first, receipt creation occurs before host refusals that happen after that
point, and artifact insertion plus receipt completion are one persistence operation.
`.builder/TRANCHE_PLAN.md` no longer says T2 is merely declared for operator review.
