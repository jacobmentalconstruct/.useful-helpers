## Declared Outcome

T7 proves truthful breadth at prototype scale:

> Explicit observation and awareness degrade usefully and honestly across a substantial
> software target, a mixed records/document target, and an empty or nascent target,
> using deterministic T3-owned substrate records and compact T4 awareness projection
> without inventing unsupported richness.

## Scope

T7 may add:

- minimal deterministic domain-signal classification owned by the T3 substrate layer or
  a small substrate-owned helper;
- substrate observations, epistemic evidence, derived claims, relations, and handles for
  domain/profile signals;
- awareness projection changes that consume only T3 substrate APIs/handles and express
  domain orientation, limitations, unknowns, and source handles compactly;
- known-answer fixtures for a substantial software target, a mixed records/document
  target, an explicitly observed empty target, and an unobserved target;
- focused T7 tests and a T7 gate under `.builder/gates/`;
- minimal CLI usage of existing substrate and awareness commands where needed to prove
  consumer-visible behavior;
- review documentation updates needed to submit T7.

The initial domain vocabulary is intentionally small. It should be sufficient to
distinguish observed-empty/nascent, software-like, document/records-like, and mixed
targets with clear supporting signals and limitations.

## Non-Goals

T7 does not implement local AI, embeddings, vector search, semantic ranking, OCR, PDF
parsing, full-text extraction beyond existing mechanics, language symbol graphs, import
graphs, package managers, domain cartridge/plugin frameworks, a broad file-type
ontology, filesystem watchers, performance optimization, GUI, MCP expansion, new
mutation behavior, rollback, release/update/removal lifecycle, remote/cloud services, or
construction-role runtime concepts.

T7 does not make awareness the owner of substrate facts. It does not make T3 substrate
own awareness projection. It does not collapse runtime receipts, App Journal memory,
epistemic evidence, awareness revisions, or mutation records.

## Ownership And Dependency Rules

T3 substrate owns deterministic domain observations, epistemic evidence, derived claims,
relations, and traceable handles. T4 awareness owns compact presentation of those facts.
CLI and MCP remain entrances. Mechanical tools remain portable operations below the
host. Runtime receipts and App Journal records are not domain-truth inputs unless a
future owner explicitly mediates them through provenance.

Any target inspection that supports a domain conclusion must be recorded through the T3
substrate owner as an observation/evidence/claim relation. Awareness may compute only
ephemeral freshness comparisons directly, as established by T4; it must not scan the
target to create domain findings.

Unknown remains explicit. An unobserved target must not be treated as observed empty. An
observed empty target may truthfully be described as empty/nascent, but only because T3
has recorded the refresh basis supporting that statement.

## Completion Evidence

T7 is complete only when evidence proves:

1. A fresh unobserved target produces awareness with unknown/missing basis and no domain
   richness.
2. An explicitly refreshed empty target produces thin truthful substrate and awareness
   records describing observed-empty/nascent state, with limitations and no fabricated
   structures.
3. A substantial software fixture produces deterministic software-domain observations,
   evidence, claims, and compact awareness findings with T3-owned round-tripping handles.
4. A mixed records/document fixture produces deterministic document/records or mixed
   profile observations, evidence, claims, and compact awareness findings with honest
   limitations for unparsed or weakly observed materials.
5. Domain claims trace through substrate relations to observations, epistemic evidence,
   and resources.
6. Awareness consumes T3-owned domain/profile handles through substrate APIs rather than
   direct T3 table ownership or target scanning.
7. Domain breadth does not create operational receipts, App Journal entries, mutation
   records, or MCP-private state merely by observing/orienting.
8. CLI and MCP can read the resulting durable world through their existing entrances
   without T7 making either entrance a capability owner.
9. Lower layers and mechanical tools do not import awareness, MCP, mutation, journal,
   receipts, construction history, or domain projection code upward.
10. No T7 implementation introduces out-of-scope surfaces.
11. Canonical pytest, Ruff, `git diff --check`, T7 gate, and cumulative T6/T5/T4/T3/T2/T1/T0
    gates pass.

## Discrimination Plan

The T7 gate must reject plausible wrong implementations:

- treating an unobserved target as observed empty;
- detecting a software or document/records target only in awareness by scanning the
  target directly;
- recording unsupported domain conclusions with no substrate evidence or trace;
- using file extensions to overclaim parsed content, such as claiming PDF text was read
  when no parser ran;
- leaking historical substrate records into the current domain profile after a refresh
  observes a different target shape;
- creating automatic App Journal entries, operational receipts, mutation records, or
  MCP-specific state from domain observation alone;
- allowing tools or lower substrate/runtime layers to import awareness, MCP, GUI,
  construction, or other higher projection code;
- passing with one generic non-empty fixture while failing to distinguish software,
  mixed records/documents, and empty/nascent targets.

## Risks

The main risk is overclaiming from weak signals. T7 must prefer thin truthful labels and
explicit limitations over impressive but unsupported domain summaries.

The second risk is ownership drift: awareness could become a second observation engine,
or the domain layer could become a premature cartridge framework. The first T7 version
should remain a small deterministic substrate-owned profile with awareness as projection.

The third risk is accidentally treating software as the default target shape. T7 must
prove document/records and empty/nascent degradation as first-class fixture paths.
