## 2. Changes

**Debris.** Cleared `_state/`, `logs/`, `_artifacts/`,
`.useful-helpers-test-tmp/` (40 files), and smoke-run residue under
`config/domain-boundary/`. All were produced by verification runs.

**Tracking.** Untracked `config/registry.json` — generated by `registry-refresh`,
and ignored before the collapse. A committed index drifts from its sources.

**The BCC now ships inert.** `templates/BUILDER-CONSTRAINT-CONTRACT.md.tmpl`
carries its four placeholders unfilled, so a freshly installed sidecar arrives
bound to nothing. The filled working copy stays in `.bcc/`, already excluded from
the vend. Installation supplies the values: the installer presents them as
editable text fields with a folder picker, pre-filled with defaults, behind a
checkbox. **Activation is installation** — no second mechanism, which is simpler
than the activation-tool design previously sketched.

**Documents corrected.** `AGENTS.md` is the agent front door and told agents
*"you normally pass no root — the default is already the target."* That became
false when root resolution was rewritten, and would have actively misled. It now
carries the four resolution cases. `README.md` described *"the project this
folder lives in"* — parent inference — and now states that the sidecar has no
target until installed or explicitly pointed.

**Version.** `0.1.0`, the unified sidecar's first baseline. It read `1.1.0` —
the toolkit's own lineage — while the repository was tagged v0.0.

**Dependencies.** `requirements-dev.txt` declares `pytest`. `tests/` needed it
and nothing said so; a fresh developer could not run the suite.

## 3. Three Gate Assertions Were Wrong, Not the State

Recorded because the pattern matters more than the fixes.

1. **"exactly one commit"** — a tranche may legitimately need several. Replaced
   with the real invariant: history has a **single root**, so no predecessor
   history was grafted in behind ours.
2. **"`_state` and `logs` are absent"** — running the sidecar regenerates them,
   and *the gate itself invokes the sidecar*. The check could never pass.
   Replaced with: runtime output is never **tracked** and never **packaged**.
3. **"no path containing `/smoke-`"** — swept up legitimate predecessor fixtures
   in the parts bin. Scoped to our own `config/` tree.

Each was caught by running the gate rather than by reading it. A gate that is
never run is a document, not a mechanism.

- **`smoke_test.py` has never been observed to pass.** It exceeds three minutes
  on every attempt over this filesystem mount. "Cleanly installable" is
  therefore verified by the gate but **not** by the project's own self-check.
- **`tests/` has not been run.** `pytest` is unavailable in this environment; it
  is now declared, but the suite remains unexercised here.
- **Windows is wholly unverified** — `run.bat`, the Tk entrances, venv
  interpreter resolution, Windows path handling.
- **`VERSION` does not move when tools change.** A stale copy once declared
  `1.1.0` while carrying 78 tools against the real 95.
- Two manifests still describe what ships: `_PAYLOAD_EXCLUDE` in the harness and
  `CLEAN_APP_STRIP` in `vendor_export`. Convergence belongs to T1.
- `packaging/` is excluded from the vend, yet the installer is deliverable #1.
