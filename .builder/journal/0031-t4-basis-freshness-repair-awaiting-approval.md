## Repair scope

Entry `0030` returned T4 for a bounded implementation invariant: awareness freshness
had to bind to the T3-observed basis, not to the live target state at awareness refresh
time, and current orientation had to avoid leaking accumulated historical substrate
records after deletion or replacement-style transitions.

The repair does not redesign T4, park T4, credit P4, or begin T5.

## What changed

- Added a T3-owned `current_awareness_basis()` API in `product/core/substrate.py`.
  It exposes the latest coherent substrate refresh basis with a stable basis
  identifier/signature, resource handles current at that refresh, current claims,
  observations, evidence handles, and provenance handles.
- Added a T3-owned `target_signature()` helper so the same resource-signature logic is
  used for both the observed basis and the live freshness comparison.
- Changed `product/core/awareness.py` so awareness refresh composes from that specific
  T3 basis instead of accumulated `list_resources()` / `list_claims()` history.
- Stored the T3-observed target signature as the awareness freshness baseline. If the
  target changes after T3 refresh and before T4 refresh, the awareness revision reports
  `stale`, not `current`.
- Added adversarial T4 fixtures for `T3 refresh -> target mutation -> T4 refresh` and
  `non-empty -> T3 refresh -> delete -> T3 refresh -> T4 refresh`.
- Strengthened the T4 gate with a behavioral `basis_freshness_behavior` check that runs
  those witnesses directly.

## Red witness

Before the repair, the new focused T4 fixtures failed exactly the missing invariant:

- awareness reported `current` after a target mutation between T3 refresh and T4
  refresh; and
- latest empty orientation reported one historical resource from the prior non-empty
